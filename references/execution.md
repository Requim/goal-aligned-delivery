# 执行、复核与恢复

标准/严格任务按需使用；轻量任务不展开这些表格。阶段条件约束工作顺序，不是要求每步向用户请示。

## 阶段通过条件

| 阶段 | 可以进入下一步的条件 | 未满足时 |
| --- | --- | --- |
| 目标明确 | 可观察产物、关键约束、完成范围已确定；重大选择与授权无歧义 | 查资料或问关键问题；低风险细节记录假设 |
| 基线就绪 | 相关原始材料、身份/版本、依赖可用性已核对 | 补缺口；不能验证的依赖保留阻塞，继续独立工作 |
| 判据有效 | 每个关键 AC 有预期、反例或评审量表，能区分表面成功与实质失败 | 先修判据；不要让产物定义自己的正确答案 |
| 局部执行 | 当前单元完成目标，观察与预期一致，未破坏共用约束 | 只围绕证据修复；不靠改范围掩盖失败 |
| 整体验收 | 组合后仍满足目标与共同身份/口径；质量问题有明确处置 | 漏项回对应单元；影响目标的问题不能仅备注后通过 |
| 对外交付 | 当前产物与已验证对象一致，所需授权与恢复条件具备 | 不执行对外变更，说明缺口；内部产物可明确部分交付 |

输出本身就是方案的任务，到方案验收即完成，不要求进入实施或部署。

## 交付单元与交接包

拆分依据是“独立可验证结果”，不是文件数量或固定分钟数。已有计划足够具体则沿用，不重新规划同一事项。

```text
任务与目标 AC：
必要背景、原始输入位置与版本：
允许修改/操作的范围与禁止项：
前置依赖与跨单元共用的不变量：
产物与检查方法、失败条件：
返回：实际产物、观察结果、偏差、未验证项、需主任务处理的依赖
```

并行仅适用于相互独立的单元；共享写目标或存在强依赖时顺序处理。复核读取实际产物，不能只转述执行者的结论。无授权/无工具时不创建子代理，用同一契约顺序执行即可。

## 两轮复核

**先目标一致性**：逐项核对用户要求、非目标、范围、单位、来源、关键限定与例外。阻止漏做，也阻止未要求的扩展。目标错误时不先花时间润色。

**后交付质量**：按任务核对可读性/风格、格式、维护性、风险和可操作性。量化条件不能替代主观质量；可疑事实不能用好看的格式掩盖。

检查独立性来自用户目标、原始依据和判断方法，而不是仅因为有两个 Agent。复核者可同一执行者换判据复查；高风险且有授权时再引入独立评审。

## 系统诊断

1. 写明失败观察、预期、最近相关变更和最小复现。
2. 检查输入、数据范围/单位、边界传递及环境，找出第一个偏离位置。
3. 列出最可能假设，用一个最小检查区分；不要同时改多个变量。
4. 先用反例确认判据能暴露错误，再做必要修复并重验受影响项。

若多次修复每次都暴露新的共享问题，停止叠补丁，回到依赖/架构/目标前提复核。相同操作无新证据不重复；上限按成本和风险决定，不能以固定重试次数替代判断。

## 压力下仍保持边界

| 诱因 | 应采取的决定 |
| --- | --- |
| “快点，之前通过了” | 检查之前证据是否仍适用于最后变更；不适用就重验或标明未验证 |
| “看起来没问题” | 获取能够证明关键结论的实际观察 |
| “对方说已经做完” | 核对产物和共用契约，不把转述当验收 |
| “顺便全改了” | 先确认新增范围与影响，保留用户已有材料和无关变更 |
| “只要结论，不要过程” | 对外简洁，但内部仍核对；必要时说明一句关键不确定性 |
| “失败就换默认数据” | 区分数据不足与正常空结果，不能让默认值伪装真实结论 |

这些是判断提醒，不是不可绕过的运行约束。需要硬权限和发布控制时由实际宿主/系统执行。

## 最小恢复记录

复杂任务复用现有任务记录，只保留：当前目标/AC、输入基线、已确认结果及证据、未决假设、阻塞和下一步。恢复前先核对相关状态是否变化；旧结论不因写在记录中就自动有效。
