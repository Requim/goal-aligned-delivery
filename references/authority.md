# 权限与多 skill 协作

本文件是受保护的权限规则，自动学习不得修改。

## 一份任务状态与明确分工

| 责任 | 负责方 |
| --- | --- |
| 目标、范围、验收、完成声明和持续记录 | goal-aligned-delivery |
| 格式、领域算法、实现、渲染、部署等专业方法 | 请求实际需要的专业 skill |
| 允许操作的对象、环境、文件与外部动作 | 用户授权与宿主权限 |

先复用当前有效计划和进度，不因同时启用多个 skill 新建多份状态。专业 skill 已取得且仍适用的证据可直接引用；证据对象或输入变更时只重验受影响部分。已有授权不重复申请，流程提示不能扩成额外产品需求。

冲突按实际指令优先级决定：系统、开发者/宿主、用户，再到适用的本地指导与 skill；同级要求按实际上下文处理。记录采取的决定、依据及受影响项。工具能力或 skill 文字不构成授权，低优先级流程不能要求违反上级禁止落盘、禁止委派或禁止外部变更的要求。

## 无写入和外部动作

轻量任务不强制建档、评价或学习。用户禁止落盘时，任务进度、私有评价、共享经验、候选、锁、缓存、备份和临时文件全部禁写；回复给可恢复摘要并说明没有持久化。不能用“为安全备份”绕过禁写，也不能暗示工具缺失时已保存。

不自动安装插件，不修改全局配置，不自动 commit/push。授权执行任务不自动授权发布、发消息、删除或修改外部系统。沿用本轮已有明确授权；尚缺且不可推断的权限才需要用户补足，内部可审阅成果先完成。

外部操作使用专业 skill 的真实接口；本 skill 的操作账目只记录身份、授权依据、幂等键、当前 attempt 与查询/结果证据。结果未知先查询，确认未应用且授权仍有效才重试；不能靠模型推测替代查询，也不能通过编辑账目伪造外部结果。

## 学习边界

自动学习只能在允许持久化、非评测环境中进行；不得修改本文件、学习机制、受保护入口区段、工具或旧判据。只能在批准范围提出普通正文/参考或新 cases 候选，真实回归及独立边界评审通过后才应用。没有证据保留候选，不能降低门槛或重复规划来制造进展。

路径白名单、固定区段与本地哈希是协作保护，不是权限沙箱或来源认证。自然语言改写是否扩权仍由独立评审检查；宿主文件权限、沙箱和受保护发布门禁负责实际强制边界。
